# Probability of a White Christmas — CONUS dashboard

A Python pipeline plus a static dashboard for GitHub Pages. It maps the historical probability of **at least 1 inch of snow on the ground on December 25** across the contiguous U.S., using NOAA NCEI's **1991–2020 U.S. Climate Normals**.

* **Data:** NCEI's station table behind the Climate.gov "Historical Probability of a White Christmas" map — <https://www.ncei.noaa.gov/media/3501> (`Christmas_day_snow_statistics_1991-2020_updated.xlsx`).
* **Map:** pannable/zoomable Leaflet map (vendored, no CDN), CONUS-fit on load, click-to-read value, station layer, station search, adjustable surface opacity.
* **Colour:** ColorBrewer **Blues**, 9-class sequential. On the dark basemap the anchor is flipped (low = dark navy, high = near-white), mirroring NOAA's own white = >90 % convention.

```
pipeline/            Python: fetch → parse → IDW surface → mask → classify → PNG/JSON
site/                Static page (index.html, app.js, style.css, vendor/leaflet)
site/data/           GENERATED by the pipeline (git-ignored)
data/raw/            Cached inputs. Drop a manual copy of the NCEI .xlsx here if needed
tests/               pytest (synthetic fixtures only)
.github/workflows/   Build + deploy to GitHub Pages
```

## Deploy to GitHub Pages

1. Push this folder to a GitHub repo (default branch `main`).
2. **Settings → Pages → Build and deployment → Source: GitHub Actions.**
3. Push (or run the workflow manually). It runs tests, builds `site/data/`, and publishes `site/`.

Your page will be at `https://<user>.github.io/<repo>/`. The data only changes when NOAA issues new Normals (next ~2031), so there is no schedule; the downloaded inputs are cached.

## Run locally

```bash
pip install -r requirements.txt
python -m pytest -q
python -m pipeline.build            # downloads inputs, writes site/data/
python -m http.server -d site 8000  # open http://localhost:8000
```

Useful flags: `--stations FILE` (use a local copy, no download), `--prob-col "<exact header>"`, `--step 0.04` (pixel size in degrees), `--demo` (**synthetic** data for previewing layout offline; the page shows a "DEMO DATA" banner).

### If NCEI blocks the download

Some environments (and occasionally CI runners) can't fetch from `ncei.noaa.gov`. Download the spreadsheet in a browser, save it as `data/raw/Christmas_day_snow_statistics_1991-2020_updated.xlsx`, and commit it; the pipeline uses a file already in `data/raw/` without touching the network.

### If the column detection fails

The loader finds columns by header text (latitude, longitude, and a "snow depth … probability" column). If the table has a different layout, or more than one equally plausible probability column, it stops and prints every header it found rather than guessing. Re-run with `--prob-col "<exact header>"`.

## Method and caveats

* NOAA publishes **station** probabilities. The continuous surface here is this project's own **inverse-distance-weighted** interpolation (16 nearest stations, power 2), masked to CONUS land. It is **not** NOAA's interpolated surface, and it has no terrain awareness: valley-biased stations in the mountain West get smoothed across the ranges. Click a station dot for the underlying NOAA-derived value.
* Area shares in the dashboard are area-weighted (∝ cos² lat on the Mercator grid) over the interpolated surface.
* This is climatology, not a forecast.
